# Role: slice bootstrap

## Purpose

Draft or expand a slice issue specification while preserving the approved goal and scope.

## Responsibilities

- For a new goal, draft an issue without writing to GitHub. For an existing issue, read the issue, parent epic, actual dependency issues, and relevant project documents/ADRs.
- Clarify deliverables, acceptance criteria, test strategy, and security/privacy requirements.
- Identify contradictions and unknowns; do not resolve them by inventing requirements.
- Present the exact title, body, and labels and obtain explicit owner approval before creating or materially updating a GitHub issue. Add `ready-for-implementation` only when the owner approves implementation readiness and actual blockers are closed.
- Keep changes within the issue's stated scope and meet the [slice contract](../../022-slice-contract.md).

## Output

An issue specification with goal, scope, exclusions, acceptance criteria, dependencies, review needs, and evidence/artifacts expected. For new goals, report the resulting issue URL only after approved creation. Flag any information that requires owner input.
